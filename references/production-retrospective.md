# 制作复盘与强制检查

这份清单来自真实制作中已经出现过的问题。它的作用不是记录一次性的修图意见，而是把它们变成每条片子都要经过的检查。

## 先定画面，再开始编码

在生成组件前，先为每个镜头写清四件事：

1. 这句口播要让观众理解什么。
2. 应该使用生活例子、黑底知识卡、截图聚焦还是章节开幕。
3. 主体画面、标题、说明和字幕分别落在哪里。
4. 什么词触发人物动作、卡片出现、当前项点亮、截图框选或音效。

如果同一种信息结构在同一条视频里出现多次，必须复用同一套版式。三项选择不能一页做等高卡片、下一页又做底部散列；四步流程不能一页等距、下一页手填不等距坐标。

## 词级同步的四道检查

每个视觉动作必须由最终配音的词级 ASR 或强制对齐结果驱动。固定秒数、场景均分、根据字数估算都不可靠。

每个锚点要同时通过：

1. ASR 能找到与脚本一致的实际词串。不能只凭原稿猜一句 ASR 未识别出的词。
2. 锚点落在它所属页面的可见期内。
3. 从锚点出现到页面结束，保留至少 36 帧可阅读时间。
4. 同一时刻只突出正在讲的项；讲过的项降亮度，未讲项不抢先出现。

使用脚本生成和检查锚点后，再建立页面可见期清单：

    node scripts/build-visual-anchors.mjs timing.json aligned-items.json visual-anchor-spec.json visual-anchors.json --write-timing
    node scripts/check-visual-anchors.mjs timing.json visual-anchor-spec.json visual-anchors.json
    node scripts/check-visual-bindings.mjs src/YourComposition.tsx visual-anchor-spec.json
    node scripts/check-anchor-scene-windows.mjs visual-anchor-spec.json visual-anchors.json scene-windows.json

页面标题可以从该段真实口播的开始帧进入。除此以外，重点、列表、人物动作、截图框选、音效和片尾收束不得再手填出现帧。

## 版式和画面检查

- 固定顶部进度区、主体区和底部字幕区。白底 16:9 画框与黑底主要图形都在主体区内，整体水平和垂直平衡。
- 进度线和圆点的中心在同一条水平线上；人物始终在线上方，并按完整章节时间移动。
- 白底只放一到三条短重点，并只放在素材的安静区域。四项以上内容使用黑底知识卡。
- 白底同一场景持续约五秒以上，准备同机位的三张连续动作图，并按口播锚点切换。
- 具体产品优先使用可使用的透明高清 Logo、公开截图或自己的录屏。截图裁到目标，目标置于框的中心，其他界面压暗或以圈选和放大镜辅助。
- 只有一个目标需要细看时才使用中央聚焦。列表、选项和步骤保持原位点亮。
- 没有叙事作用的小方块、星号、空卡、额外外框和一秒闪页全部删除。

## 碰撞检查不是肉眼补救

为每页的标题、说明、卡片、按钮、截图框、人物和字幕区登记矩形。渲染前检查：

1. 所有元素在各自可用区域内。
2. 不属于同一组件的文字与外框不相交。
3. 标题、说明、列点之间留出至少一个字号的竖向间隔。
4. 需要居中的主标题、关系图、步骤组和收束文案，其合并中心接近主体区中心。
5. 同一组卡片的宽高、起点、间距和对齐方式一致。

先让检查失败，再修坐标；不要等到导出后才发现压字、偏移或字幕碰撞。

## 最终成片复核

不能用旧渲染或开发预览代替最终成片。每次改动后应从最终导出的视频抽查：

- 每一页进入前、口播锚点首帧、下一锚点前、退出前。
- 固定片头、每个章节开幕、每个白底动作、每个黑底知识卡、每张截图页和结尾。
- 字幕断句是否优先服从标点和自然短语，且不显示逗号、句号、问号、感叹号。
- Logo 是否清晰且在深浅底色上有足够对比。
- BGM 是否明显低于人声。

任何一项未通过，都回到导演分镜和时间线处理，不把问题留给下一条片子。
